# 架构与开发说明

本文面向维护者和需要排查兼容性问题的用户。安装与日常操作请先看 [README](../README.md)；正常使用不需要修改下面的配置。

## 运行构成

本项目是一个独立的 DSH bundle，声明自己的浏览器页面类型和引用菜单，不替换原版「浏览器」插件，也不修改 Conversation 或 Session 数据结构。Host 入口只校验配置；浏览器页面、内容读取与引用交互在 Client 中完成。

| 目录或文件 | 职责 |
| --- | --- |
| [index.mjs](../index.mjs) / [config.mjs](../config.mjs) | 声明并校验部署配置 |
| [src/browser](../src/browser) | 通过公开的 Desktop bridge 获取网页载体，管理页面生命周期、来源与代际 |
| [src/readers](../src/readers) | 网页与本地 HTML 正文、企微选区、B站字幕及授权文件读取 |
| [src/client](../src/client) | 引用菜单、文件入口、截图圈画与元素批注、错误提示及原生草稿入稿 |
| [cordis.patch.yml](../cordis.patch.yml) | 安装时只插入本插件，并提供明确的默认部署值 |
| [lib](../lib) | 随仓库提交的 Host / Client 预构建产物 |

原生网页使用宿主的沙箱、隔离和权限策略。引用浏览器按工作区或会话取得自己的网页载体；普通 Web 部署缺少所需桌面桥接时，会明确显示不可用，不以替代服务器模拟成功。

## 各类内容如何读取

### 普通文章与选区

[文章读取器](../src/readers/article.ts) 内联官方 Defuddle 0.19.6 浏览器分发，在 DOM 副本上提取 Markdown，不修改实际页面，不让通用解析器额外请求资源。已适配的文章模板使用限定正文根；未知页面仍会保守拒绝工具栏、导航或整页 body 候选，不以整页可见文字兜底冒充正文。

普通网页选区由显式操作读取。手动粘贴则单独标记为用户输入：页面 URL 和标题只是上下文，`sourceVerified:false` 不证明输入文字来自该页。插件不监听全局粘贴，不读取系统剪贴板。

### 企微文档

[企微选区读取器](../src/readers/wecom-selection.ts) 仅面向已核实版本的 Melo 接口。它先检查复制权限，再读取现有选区；对已识别的范围包装器进行只读解包，由 SDK 验证范围后读取文字，不重置、扩大或移动选区，不调用剪贴板写入或编辑方法。

接口版本或范围格式不匹配时拒绝读取，不猜测私有方法。静态定义与类型诊断受过滤和字节限制，不返回运行时成员值。用户自行 Ctrl+A 后引用仍是“当前选区”，不能据此宣称完整全文。

[文档快照读取器](../src/readers/wecom.ts) 由「企微正文（已加载部分）」触发。标准 DOM 文档只标记已加载快照，未验证完整性，不包含图片或附件；Canvas 整份正文自动提取未完成，也不回退成工具栏文字。插件不提供企微文档编辑功能。

### B站视频

[B站读取器](../src/readers/bilibili.ts) 先读取页面信息与已加载的标准字幕轨道。需要站点字幕请求时，[字幕请求实现](../src/readers/bilibili-subtitles.ts) 根据当前 URL 查询公开视频信息，核对视频和分 P，再向站点播放器自身使用的带签名播放器信息接口请求字幕列表；签名密钥每次从站点密钥接口获取，MD5 与密钥置换在插件内实现，不加载外部脚本。站点已停用旧无签名接口的可用字幕地址，插件不再请求它。轨道来源固定排列：先取与当前分 P 标识绑定的签名字幕列表（同时提供人工与自动轨道时优先人工），列表不可用时才回退本页播放器自己已请求过的字幕地址（通过只读的 Resource Timing 获得，不拦截、不修改页面；站内切换视频会在同一文档内保留先前视频的请求记录，因此该回退排在最后）。字幕 cue 的结束时间明显超过当前分 P 声明时长时按串视频轨道拒绝，不当作当前视频字幕返回。引用会标注轨道来源、语言代码、是否自动生成，以及字幕覆盖时段与分 P 时长的对比——自动生成轨道可能仍在生成、只覆盖部分时段，插件不核对字幕与音画的一致性。

一次操作至多进行五次正常只读请求（视频信息、签名密钥、带签名的播放器信息、至多两个字幕文件），无自动重试，并共享一个可配置的总超时。站点 API 请求由浏览器按规则携带当前会话 Cookie，插件不读取 Cookie 值、登录对象、令牌或凭据存储。字幕资源仅接受已知 HTTPS 站点和路径，包括正常 AI 字幕的无扩展名地址；不跟随重定向，响应仍须通过 UTF-8 JSON 与字幕条目校验。

签名字幕地址、原始异常和响应内容不进入诊断。失败详情仅投影阶段、失败类别、HTTP 状态与数字 API 状态码，只在界面中展示，不加入模型引用。字幕未取得时可以单独引用页面信息，但必须保留缺字幕说明；字幕成功也不等于分析过音频、画面或完整视频。

### 本地 HTML 与批注

本地 HTML 的文件菜单与预览工具栏入口使用来源会话的文件权限读取完整快照和已声明的直接资源。原生 guest 保持官方 lease 初始页，用户 HTML 仅在不透明的沙箱子框架执行；固定消息操作不携带可执行代码或磁盘读取请求。正文提取复用同一 Defuddle 核心，来源路径、资源地址和版本由文件读取器提供，不接受页面自报的文件身份。支持范围见 [本地 HTML](local-html.md)。

截图仍由原生 guest 取得；圈画编辑器合成 PNG，元素点选提供位置与可见文字等不可信提示，不能据此宣称已定位源码组件。原生页面、子框架或会话变化会阻止旧捕获入稿。操作与边界见 [圈画和元素批注](annotations.md)。

## 草稿、来源与模型输入

文字使用宿主原生紧凑 quote，图片通过原生 PNG 草稿附件流程加入。来源包含经过认证参数清理的 URL、标题、时间、内容类型与必要的范围说明，统一标记为外部不可信资料。

完整正文保存在原生引用中，而不是插件私有的短标题映射。用户最终发送时，宿主将其展开为普通用户消息并写入会话日志；视觉折叠不减少文字 token。图片能否被理解及成本由所选模型和宿主原生图片流程决定。

入稿保留原草稿，不提交消息，也不替换用户选中的已有文字。操作开始时记录插入位置和草稿修订；捕获期间编辑草稿、切换会话、导航或销毁页面，会使旧结果不能直接写入新的状态。图片附件与引用在同一个同步入稿步骤中检查；意外结果无法确认时提示用户先检查草稿，不宣称已经回滚。

失败保留内容与手动输入只存在会话内存，不是持久备份。点击“添加保留内容”会用当前预算重新检查已有内容，而不是重新抓取网页。浏览器的最后导航地址和登录状态不承诺跨插件或应用重启恢复。

## 可选配置

随包的 [配置补丁](../cordis.patch.yml) 已提供以下值。它们是大小和超时保护，普通安装无需手动设置；只有内容超限或确需调整时才修改。

| 字段 | 随包值 | 含义 |
| --- | --- | --- |
| `maxTextBytes` | `65536` | 完整引用文字、来源与原生格式标记的 UTF-8 字节上限，也约束字幕文件读取；三个固定站点元数据接口的响应上限为固定的 4 MiB（B站合集视频的 view 响应可超过 150 KB） |
| `maxImageBytes` | `10485760` | PNG 与相关捕获元数据预算；最终原始图片字节也会检查 |
| `subtitleRequestTimeoutMs` | `15000` | B站字幕请求的总超时，单位毫秒 |
| `localHtmlMaxBytes` | `16777216` | 本地 HTML、资源与完整编码包装的字节预算 |
| `localHtmlMaxFiles` | `64` | 直接本地资源数量上限 |
| `localHtmlTimeoutMs` | `15000` | 本地文件准备与有限框架请求超时，单位毫秒 |

大小与数量必须是正安全整数；两项超时范围均为 1 至 2147483647。完整内容超限时拒绝，不静默截断。客户端从宿主配置快照读取值，不自行推断缺失字段；Host 配置表为新增项提供默认值。缺少或无效的配置会明确报错，旧开发挂载需加载新版 Host 模块。宿主模块或 bundle 变化后应彻底退出并重启 DSH，不能仅刷新客户端。

插件只清理来源 URL 中的认证参数，不承诺自动识别并移除正文或截图中的所有敏感信息；发送前由用户检查。

## 兼容性与验证范围

当前实测宿主为原版 DSH Desktop 0.2.2-rc.1，需要 Desktop Browser bridge protocol 1、原生 quote、真实插入位置与图片附件接口。版本范围声明不是对所有版本的逐一验证；网站接口也可能独立变化。缺少能力时明确拒绝，不自制另一套引用节点或绕过页面权限。

v0.2.0 发布时通过 489 项插件回归和包级类型检查；独立临时目录的 Host 冷导入、客户端模块注册及原版 CLI 隔离安装已通过。用户在开发挂载下确认了紧凑引用、PNG、企微选区、文章和 B站字幕；这些不等于在独立 profile 中完成了 GUI 全流程验收。历史记录见 [原版宿主与选区验证](validation-2026-11-14-standalone.md)，发布范围见 [发行说明](../RELEASE_NOTES.md)。

v0.3.0 在相同实测宿主范围内发布，新增圈画、元素批注、本地 HTML 与共享正文入口；已通过 720 项插件回归、构建后 noEmit 和包检查。用户在开发挂载下确认了新增功能；隔离框架的真实浏览器检查与原生接口模拟测试仍有不同范围，见 [本地 HTML 验证记录](validation-2026-11-19-local-html.md)。

v0.3.1 修复 B站字幕引用：签名字幕列表接口、固定的来源顺序、串视频轨道拒绝与合集大响应预算，见 [发行说明](../RELEASE_NOTES.md)；已通过 747 项插件回归、构建后 noEmit、包检查，并以匿名会话完成真实 B站接口的端到端验证。

## 源码开发与包验证

普通安装用户使用 Release 或仓库自带的 `lib`，不需要构建工具。源码开发需将本仓库检出到已准备好 SDK、声明和开发依赖的 DSH 源码树下的 `dsh-browser-context/` 子目录，再在 DSH 源码树根执行：

```sh
node dsh-browser-context/scripts/build.mjs
node dsh-browser-context/scripts/test.mjs
node dsh-browser-context/scripts/check.mjs
```

构建复用该源码树的官方 clientBundle / tsdown、TypeScript、Vitest 与 React，不支持在任意独立目录仅运行 `npm install` 后直接编译。源码更改后必须重建并提交 `lib`；不要手工修改生成文件。

仓库 CI 不依赖 SDK 编译，而是对已提交产物打包，再执行 [包验证脚本](../scripts/verify-package.py)。它检查载荷白名单、包内目标、许可、安装钩子和凭据模式，并在无 node_modules / SDK 的临时目录导入 Host、捕获客户端注册；不启动 DSH App，不将模块检查称为真实页面读取验真。
